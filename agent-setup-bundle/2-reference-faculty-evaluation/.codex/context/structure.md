# Relevant project structure

Updated: 2026-11-03

Verification status: current feature/page directories, route composition and page imports inspected on 2026-11-03. Root-level login/auth/auth-log page locations and their current route imports were rechecked after the manual move. No tests or typecheck were run for this page-context update. Previously recorded parent validation ran `npm run typecheck`; it failed on known pre-existing issues: `AlertProps.title`, `AuditLog.timestamp`, nullable pagination/ID/limit values in subjects/classes/employee, optional `sortFields`, and unrelated test type errors. Earlier stale feature-module resolution errors in auth tests are gone. No test suite was run; previous validation below predates regrouping.

- React, TypeScript, React Router, Vite and Tailwind are configured in `package.json`; Vitest, ESLint and Prettier provide project checks.
- `src/routes/index.tsx` owns router composition and guard transformation. Its authenticated root registers staff Academic and Administration routes, auth routes, student enrollment and student evaluation routes.
- `src/features/faculty/grade-encoding/` owns grading routes, service/query contracts, access, schemas, draft/leave-warning hooks and editor/filter/table components. Its route module remains mounted beneath `/academic`; `src/pages/faculty/grade-encoding/{GradeFaculty,GradeSubjects,GradeStudents}.tsx` implement its three-page cascade.
- `src/features/students/evaluation/` owns student evaluation and `student.routes.tsx`; `src/features/students/enrollment/` owns self-enrollment and `self-enrollment.routes.tsx`. These routes mount directly under the authenticated root.
- `src/features/staff/academic/` contains `evaluation/{reports,classes}`, `students` and `enrollment`. `academic.routes.tsx` composes these route modules plus faculty-owned Grade Encoding under `/academic`.
- `src/features/staff/administration/` contains `employee`, `users` and `access-control`. `administration.routes.tsx` composes their routes, Windows Config and auth-log routes without an Administration URL prefix.
- `src/features/other-shared/{login,auth,auth-logs}/` holds cross-role login, session/auth and audit-log features. Audit-log routes are presented under Administration despite this filesystem ownership.
- `src/features/shared/access/users-access.config.ts` owns shared role/scope constants. Existing shared API lookup modules remain in `src/features/shared/{academic-terms,campuses,colleges,programs,roles,scopes,subjects}/`.
- Portal pages are grouped under `src/pages/`: `faculty/grade-encoding`, `students/{evaluation,enrollment}`, `staff/academic/evaluation/{reports,classes}`, `staff/academic/{students,enrollment}`, `staff/administration/{employee,users,access-control}`, and root-level `{login,auth,auth-logs}`. These cross-role pages do not use an `other-shared` page directory; their feature modules remain under `src/features/other-shared/`. Windows Config lives directly in `staff/administration/WindowsConfig.tsx`; Not Found lives in `shared/NotFound.tsx`. Tests remain under `src/tests/`; page ownership does not change URL nesting.
- `src/components/SidebarNavigation.tsx` consumes staff Academic, student enrollment and student evaluation routes for the Academic section, and Administration routes for its Administration section. `src/routes/sidebar.ts` derives accessible navigation items; Grade Encoding retains its access callback.
- `src/routes/paths.ts` defines canonical Evaluation, Grade Encoding, Students and employee destinations.
- `/windows-config` is registered by `src/features/staff/administration/administration.routes.tsx`; `src/pages/staff/administration/WindowsConfig.tsx` selects a shared academic term and coordinates enrollment, evaluation and grading window editors owned by their respective features.
- `src/helpers/zod/` contains shared Zod 3 schema builders. Application schemas retain native Zod composition where no helper exists.
- `src/features/staff/administration/access-control/ManageUserGroup.tsx` coordinates group editing and saving. `helpers/hydrate-access.ts` and `helpers/build-editor-assignments.ts` handle editor hydration and assignment payload construction; `groups.schema.ts` defines group schemas.
